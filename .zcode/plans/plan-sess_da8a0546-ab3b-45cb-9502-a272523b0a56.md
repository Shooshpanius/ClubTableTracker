# Три доработки: календарь (пер-событийные цвета+легенда+бейджи), мини-галерея событий, отметки игроков

## Часть A. Доработка календаря (все 3 поверхности)

Требования: у каждого события свой цвет; при открытии внизу сразу легенда мероприятий выбранного месяца с цветами; в клетке под датой — бейджи событий этого дня.

**Общая логика** `clubtabletracker.client/src/utils/eventCalendar.ts` (делится, не дублируется):
- `EVENT_PALETTE` = 18 цветов (текущие значения GAME_SYSTEM_COLORS); `eventColor(id) = EVENT_PALETTE[id % 18]` — детерминированно, одинаково на вебе и в Flutter (Dart-формула та же).
- `monthEvents(events, year, month)` — события, пересекающиеся с месяцем (кампании — покрытием любого дня месяца, турниры — по диапазону), отсортированные по StartTime.
- `campaignsCoveringDay` / `singleEventsOnDay` — остаются. Цветовой признак «система» и фильтр по системам убираются.

**Компоненты** `components/EventCalendar.tsx` + `components/legacy/EventCalendar.tsx` (зеркально):
- Полосы кампаний — как было, но цвет = eventColor (у каждой кампании свой; пересечения по-прежнему делят клетку на полосы).
- Под датой вместо точек — ряд бейджей всех событий дня: кампания = квадратик 8px со скруглением, турнир = кружок 8px, цвет события; максимум 4, дальше «+N»; завершённые — приглушены.
- Легенда под сеткой (видна сразу при открытии): список мероприятий выбранного месяца — цветовой свотч + ⚔️/🏆 + название + даты («1–20 сен» / «13 сен, 11:00»); клик по пункту — перейти к дате начала события (смена месяца при необходимости + выбор дня, откроется панель дня). Старые чипы систем и hiddenSystems-фильтр удаляются.
- Панель дня — как было, свотчи теперь eventColor.

**Flutter** `MobileFlutter/lib/widgets/event_calendar.dart` — те же изменения (палитру eventColor продублировать формулой `id % palette.length`); смоук-тесты обновить (легенда теперь содержит названия событий, а не чипы систем).

## Часть B. Мини-галерея + описание события

**Бэкенд** (по образцу клубной галереи ClubPhoto / ClubAdminController:1079-1129):
- Модель `Models/EventPhoto.cs`: `Id, EventId, ClubEvent, Url, OrderIndex`; DbSet + FK (cascade) в `AppDbContext`; миграция `AddEventPhotos` (автоприменяется на старте — Program.cs:78).
- `ClubAdminController`: `POST events/{id}/photos` (IFormFile `file`, ≤10 МБ, jpeg/png/webp/gif + magic bytes по готовым константам, лимит 12 фото на событие, путь `uploads/clubs/{clubId}/events/{eventId}/gallery/{Guid}{ext}`, OrderIndex=max+1) и `DELETE events/{id}/photos/{photoId}` (удаление файла + строки).
- Проекции событий (EventController:33-40 и ClubAdminController:468-475): + `Photos = [{Id, Url}]`.

**Веб-участник** (ClubPage.tsx + legacy, все 4 блока карточек): в `ClubEventItem` + `photos?`; под описанием — лента миниатюр 64×64 (горизонтальная прокрутка), клик — полноэкранный модал (страничный state `eventPhotoModal`, по образцу galleryPhotoModal, ×2 дизайна).
**Веб-админ** (ClubAdminPage.tsx + legacy): в карточке события — кнопка «📷 Фото» (скрытый input, accept как у галереи), загрузка/удаление через новые эндпоинты, миниатюры с «×».
**Flutter-участник**: модель ClubEvent + `photos`; в карточке горизонтальная лента миниатюр (`resolveMediaUrl`), тап — существующий `_showPhotoViewer`. Загрузку в Flutter-админке не делаем (там вообще нет multipart — как и для регламентов).
**Описание**: отображение уже есть везде; админ-редактирование есть на вебе. Закрываю пробел: в Flutter-админке (`club_admin_screen.dart`) добавить поле описания в форму создания/правки события (payload уже поддерживает Description).

## Часть C. Отметки игроков — значки + история («И то, и другое»)

Без бэкенда: агрегация на клиенте из уже загруженных событий клуба (`participants[].place`, eventType, status; берём не-архивные — как везде в приложении).

**Веб** (ClubPage.tsx + legacy):
- Хелпер `playerEventStats(userId)` → { gold, silver, bronze, campaigns, tournaments, history: [...] } (история — обратная хронология: иконка, название, система, даты/диапазон, место-бейдж или «участник», завершённые приглушены).
- Карточка/строка игрока (4 блока): компактные чипы достижений — 🥇×n, 🥈×n, 🥉×n, ⚔️×n (макс. 4 вида).
- Имя игрока кликабельно → модал профиля (state `playerProfileModal`, по образцу playerSystemsModal, ×2 дизайна): шапка (имя, город, в клубе с…), чипы достижений, список истории событий.

**Flutter** (`club_screen.dart`): тот же хелпер; чипы в карточке игрока (`_buildPlayersTab`), тап по карточке → `showModalBottomSheet` с профилем и историей.
