# План: редактирование столов, итоги и архив турниров (веб)

Контекст: «турнир» = `ClubEvent` с `EventType="Tournament"`. Сейчас столы (`TableIds`, CSV-строка) задаются только при создании, статусов/итогов/архива нет вообще.

## 1. Редактирование столов после создания

**Backend** (`ClubTableTracker.Server\Controllers\ClubAdminController.cs`, по образцу существующих `PUT events/{id}/<field>`):
- Новый DTO `EventTablesRequest(int[] TableIds)`.
- `PUT /api/clubadmin/events/{id}/tables`: валидация что все столы принадлежат клубу, запись `ClubEvent.TableIds = string.Join(',', ...)`.

**Frontend** (`clubtabletracker.client\src\pages\ClubAdminPage.tsx`, вкладка events, ~строка 1109+):
- Для каждого существующего события — кнопка «Столы», открывающая тот же чекбокс-список столов, что и при создании (переиспользовать логику `selectedEventTables`), с сохранением через новый эндпоинт и обновлением `setEvents(...)`.

## 2. Итоги турнира

**Модель** (`Models\EventParticipant.cs`): новое поле `Place int?` (место; null = без места). Миграция EF.

**Backend**:
- `PUT /api/clubadmin/events/{id}/results` с DTO `EventResultsRequest(List<{UserId, Place}>)`: валидация что userId — участник, места уникальны и ≥1; сохранение мест.
- Итоги включаются в существующий GET событий (`EventController` / ClubAdmin GET) через DTO.

## 3. Архив

**Модель** (`Models\ClubEvent.cs`): новое поле `Status string` (значения: `null`/"Planned" по умолчанию → `"Completed"` → `"Archived"`). Миграция EF. Для существующих записей — null (= активный), обратной совместимости хватает.

**Backend**:
- `POST /api/clubadmin/events/{id}/complete` — переводит в `Completed` (доступно после EndTime).
- `POST /api/clubadmin/events/{id}/archive` — в `Archived` (требует `Completed`).
- GET-эндпоинты отдают `Status`; архив доступны всем пользователям клуба: фильтр в `EventController` (`GET /api/event/club/{clubId}`) уже возвращает все события — на клиенте фильтруем по статусу.

## 4. Frontend

- **ClubAdminPage** (events): кнопки на карточке события «Подвести итоги» (после EndTime; открывает список участников с полями места и сохраняет), «В архив» (после Completed). Архивированные скрываются из основного списка (отдельная свёрнутая секция «Архив»).
- **ClubPage** (игрок, desktop ~1108+ и mobile ~1558+ — зеркалируем): прошедшие завершённые турниры показывают блок «Итоги» (список участников с местами, отсортирован по месту). Новая вкладка/секция «Архив турниров» клуба с итогами.
- **HomePage** при необходимости: не показывать архивированные в upcoming/active (фильтр по `Status`).
- **Legacy-копии** (`src/pages/legacy/`) зеркалим, как принято в проекте.

## Порядок работ
1. Модели + миграции EF (`Place`, `Status`).
2. Backend-эндпоинты (tables, results, complete, archive) + DTO.
3. ClubAdminPage: редактирование столов, форма итогов, кнопки complete/archive, секция архива.
4. ClubPage/HomePage: отображение итогов и архива (+legacy-копии).
5. Проверка сборки сервера и клиента.
